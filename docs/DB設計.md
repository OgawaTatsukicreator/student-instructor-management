# βteam データベース設計

DB本体はXAMPPのphpMyAdmin等でチームが作成する。DB名はフォルダー名と同じ `βteam`。文字コードはutf8mb4、照合順序はutf8mb4_general_ci、エンジンはInnoDBを使用する。MariaDB 10.4以降／MySQL 8.0を対象とする。

空のDBを選択して、プロジェクト直下の `database.sql` を読み込む。このファイルはDB本体の作成・既存テーブルの削除をしない。元のAlphaTeam.sqlを読み込んだDBへ重ねて実行せず、バックアップを取り、空のDBへ読み込む。既存データの移行が必要な場合は別途移行手順を作る。

| テーブル | 役割 | 主な制約 |
|---|---|---|
| roles | 3種類の権限 | 名前をENUMとUNIQUEで制限。初期データあり |
| teachers | 講師とログイン認証 | メール一意。passwordはハッシュ。権限は外部キー |
| students | 生徒情報 | 生年月日必須。共有の特記事項を保持 |
| student_teacher | 多対多の担当関係 | 組の重複不可。講師削除は制限、生徒削除は関係も削除 |
| system_locks | 管理処理のロック | 競合する講師管理・担当変更を直列化 |
| rate_limits | ログイン・メール送信の回数制限 | セッションに依存しないバケット |
| password_changes | メール認証中の変更 | ハッシュ、期限、試行回数、本人のセッションとの結び付け |

`roles 1─多 teachers`、`students 多─多 teachers（student_teacherを経由）`、`teachers 1─0または1 password_changes`。担当講師は全権限を選択できる。student_id・teacher_id単独にはUNIQUEを付けない。

生徒登録では担当1名以上をアプリで必須にする。担当関係だけではDB側で最低人数を保証できないため、生徒本体と担当関係を同一トランザクションで保存する。generalの特記事項更新時は担当関係を再確認する。

versionは編集競合、credential_versionは既存ログインとメール認証の失効判定に使う。パスワード変更時は現在のセッションを更新して維持し、他のセッションを失効させる。権限IDの数値比較はせず、roles.nameで判定する。

日時は接続時にUTCを指定する。生年月日は日付として保持し、現在日との比較は日本時間で行う。メールは前後空白を除去して小文字化し、上限254文字。氏名は各50文字、特記事項はアプリで2,000文字を上限とする。

実際の管理者はSQLに固定パスワードを埋め込まず、付属のCLIセットアップで作成する。パスワードポリシーは半角の10〜50文字、英大文字・英小文字・数字・記号のうち2種類以上。

rate_limitsは古いバケットを定期削除できる。保留中情報は取消・期限切れ・ログアウト時に削除し、使用済みコードを再利用しない。実メールの送信にはSMTP設定が必要。
