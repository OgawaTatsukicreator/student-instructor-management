# セキュリティ・異常系の再検証

実データを含むDBと実際に使うアプリへ送信試験を行わない。DBはチームが作成し、検証用の別コピー・別ポート・架空データだけを使う。生成レポートはoutput、ログはruntimeに出し、Gitには含めない。

## 単体確認

プロジェクト直下で、検証済みPHPのパスを指定して実行する。

```powershell
& 'C:\xampp\php-8.2.35\php.exe' tests\unit.php
& 'C:\xampp\php-8.2.35\php.exe' tests\error_unit.php
```

40件と27件を確認する。PHPの配置先が異なる場合はパスを合わせる。専用iniのextension_dirが相対extの場合は、PHPフォルダーを作業ディレクトリにして、スクリプト側を絶対パスで渡す。Windows配布物の更新対象は[PHP更新手順](PHP更新手順.md)を参照し、実在する検証用PHPを指定する。

## HTTPの108ケース

1. ソースの別コピーを使う。実用中のconfig.local.phpはコピーしない。
2. 空の `beta_security_test_run` を自分で作成し、ローカル保管のdatabase.sqlを読み込む。
3. tests/export_sql_fixtures.phpで生成したtest_data.sqlのUSE句をこの専用DB名へ合わせて読み込む。roles3件、system_locks1件、可変5テーブル各10件になる。
4. この専用DBだけで `UPDATE teachers SET must_change_password=0;` を実行する。テスト用アカウントはteacher1〜10@example.invalid、SqlTest123!。実用DBには使わない。
5. 接続先環境変数を検証用へ明示し、PHP開発サーバーを専用ルーターで起動する。すでに使用中のポートは使わない。

```powershell
$env:BETATEAM_DB_HOST = '127.0.0.1'
$env:BETATEAM_DB_PORT = '33318' # 自分が用意した専用DBのポートに合わせる
$env:BETATEAM_DB_NAME = 'beta_security_test_run'
$env:BETATEAM_DB_USER = 'root' # 専用試験環境のユーザー
$env:BETATEAM_SECURITY_TEST_MODE = '1'
& 'C:\xampp\php-8.2.35\php.exe' -S 127.0.0.1:33319 -t . tests\security_router.php
```

DBにパスワードがある場合はBETATEAM_DB_PASSWORDを安全に設定する。上のrootは隔離した試験DBの例であり、実用DBの接続は[専用ユーザー](DB接続権限.md)にする。検証用の別コピーにconfig.local.phpを作る場合も、この専用DBの設定だけにする。

別のPowerShellで、同じコピーの直下から実行する。

```powershell
$env:BETATEAM_SQL_TEST_HOST = '127.0.0.1'
$env:BETATEAM_SQL_TEST_PORT = '33318'
$env:BETATEAM_SQL_TEST_DATABASE = 'beta_security_test_run'
$env:BETATEAM_SQL_TEST_USER = 'root'
python tests\security_http.py --base-url http://127.0.0.1:33319/
```

SQL側のパスワードはBETATEAM_SQL_TEST_PASSWORD。未設定なら空文字。MySQL CLIが既定のC:/xampp/mysql/bin/mysql.exeと異なる場合はBETATEAM_MYSQL_CLIへ設定する。HTTP送信先と、ルーターが実際に読むDB設定のホスト・ポート・DB名の一致を最初のGETで検証する。不一致ならPOSTせず終了する。ルーター自体もCLI-server・試験モード・loopback接続・専用DB名を必須にし、Apacheからは利用できない。

試験は生徒・講師・担当・認証保留の前後比較を行い、終了時に架空データを復元する。認証によるrate_limitsの更新は残る。再実行時は、専用DBだけで `DELETE FROM rate_limits;` を行う。

この環境ではMySQL CLIが終了0でも出力を途中で欠落させる現象があったため、--unbufferedと終端マーカー・件数照合を使う。出力欠落を試験成功にしたり、再送で隠したりしない。

## 生徒一覧の追加攻撃34ケース

tests/students_security.pyは、SQLi、保存型・反射型XSS、ID・ページ・パラメーター改変、権限外POST、CSRF、項目の同時送信を直列で確認する。共有XAMPPの実URLには送信できない。リソース試験と同様に、独立したDBプロセスの専用data/、架空の10件fixture、同じ接続先のHTTP環境を用意する。

BETATEAM_SQL_TEST_*をその専用DBへ設定し、HTTP側は上記security_router.phpで同じDB設定を返すようにする。DBはbeta_security_test_で始まる名前、HTTPは127.0.0.1と明示的な専用ポートを必須とする。80・443・8080・3306・3307番は拒否する。実際の@@datadirが指定した所有ディレクトリと一致することも確認する。

```powershell
python tests\students_target_unit.py
python tests\students_security.py --base-url http://127.0.0.1:33319/ --expected-datadir 'C:\Users\your-name\AppData\Local\Temp\betateam-security-run\data' --server-kind php-cli-server
```

パスとポートは自分が起動した専用環境へ合わせる。--expected-datadirの親はbetateam-、beta-security-、beta-ui-で始まる専用ディレクトリとし、共有mysql/dataは指定しない。fixture確認が不合格なら復元処理にも進まない。

送信上限80回、アカウントごとの検索は20回未満。最初に既知の架空アカウントのログイン・検索制限行だけをリセットし、終了時に業務4表を復元する。rate_limitsと採番の内部状態は完全復元の対象外。結果はoutput/students-attack/report.jsonへ保存する。

students_target_unit.pyは送信先の25ケースと通信回数上限の1ケースを、DB・HTTP・ソケットをmockで禁止して検証する。接続先確認の最初のGETも80回の上限へ含める。専用Apache CGIで実行する場合は、同等の接続先確認ヘッダーを返す所有環境を別途用意し、--server-kind apache-cgiを指定する。この引数は結果に環境差を記録するもので、Apache環境を自動構築しない。今回の[攻撃検証結果](生徒一覧の攻撃検証.md)には、実URLの読取り確認、CGIと共有mod_phpの差、ブラウザー検証の条件も記載している。

## 障害注入16ケース

```powershell
python tests\security_runtime.py --php 'C:\xampp\php-8.2.35\php.exe'
```

必要なら--iniで専用iniを指定する。OS一時領域にソースのコピーと検証サーバーを作り、設定不正、接続不能、模擬PDOエラー、セッション開始・保存・期限、ログ失敗、部分出力、致命的エラーを再現する。実DBは不要。OOMの試験を含むため、版確認で未修正PHPを拒否する。CVE修正版より古いPHPで強制実行しない。

## Apacheの67ケース

```powershell
python tests\apache_security.py --httpd 'C:\xampp\apache\bin\httpd.exe' --server-root 'C:\xampp\apache'
```

別ポート・一時Docroot・無害なファイルで現行.htaccessを試験する。既存Apache・設定・DBは変更しない。PHPをロードせず、通信量確認用のPython CGIだけを一時環境で使う。65,536バイトは許可、65,537バイトは413となることを確認する。

## リソース制限の4グループ

tests/security_resources.pyはHTTP試験より強い隔離条件を必須にする。共有XAMPPのDBへ試験用DB名を追加するだけでは実行できない。OS一時ディレクトリ直下の`betateam-security-*`に専用DBプロセスの`data/`とアプリコピー`app/`を用意する。専用DBは3306/3307以外、専用HTTPは80/8080以外を使い、すべてloopbackだけで待ち受ける。

空の専用DBへ定義と10件のfixtureを読み込み、初回パスワード変更フラグを解除しておく。接続環境変数は上のBETATEAM_SQL_TEST_*を専用DBへ合わせる。HTTP側は専用ルーターと同じ接続先を使用する。--private-rootと--private-appには用意した絶対パスを渡す。

```powershell
python tests\security_resources.py --help
```

必須引数は--base-url、--php、--private-root、--private-app。必要に応じ--iniと--reportを指定する。HTTP側のDB接続先、実際の@@datadir、アプリコピーのPHP設定、fixture件数・ID・権限を照合し、食い違えばデータ変更前に拒否する。レポート出力はプロジェクトのoutput内だけに許可する。

IPの制限行を上限値へ設定して2回だけログインを送信し、記録が増えないことを確認する。検索も境界値直前へ設定して7回だけGETし、アカウント共通制限と独立性を確認する。SELECT SLEEP(4)は専用MariaDBで1回だけ実行し、約3秒の中断と503分類を確認する。大量リクエストや高い並列度での負荷試験は行わない。

保守処理の確認では専用DBへ期限切れ各1002件と有効な各1件を作り、dry-run・1000件削除・残り2件削除・有効行保持・不正引数の拒否を検証する。生徒・講師・担当・認証保留のfixtureを終了時に復元し、専用rate_limitsは消去する。通常運用のDBへ送信しない。

MySQL 8.0本体による時間制限の試験と、通信を意図的に破棄する接続タイムアウト試験は未実施。MySQLの3024は分類の単体試験で確認する。

## 同梱依存関係

tests/verify_dependencies.phpをCLIで実行する。ネットワーク・DBへ接続せず、公式と照合済みの5ファイルと版を確認する。不一致時に期待ハッシュを自動更新しない。[同梱ライブラリ](THIRD_PARTY.md)を参照する。

## 結果

output/security-http.json、security-runtime.json、apache-security.jsonに結果を保存する。失敗時の終了コードは1。失敗を削除・無視して完了扱いにしない。問い合わせID・安全なログ・内部情報非露出、HTTP状態、更新の有無も確認する。
