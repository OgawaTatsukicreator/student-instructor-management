# セキュリティ・異常系の再検証

実データを含むDBと実際に使うアプリへ送信試験を行わない。DBはチームが作成し、検証用の別コピー・別ポート・架空データだけを使う。生成レポートはoutput、ログはruntimeに出し、Gitには含めない。

## 単体確認

プロジェクト直下で、検証済みPHPのパスを指定して実行する。

```powershell
& 'C:\xampp\php-8.2.35\php.exe' tests\unit.php
& 'C:\xampp\php-8.2.35\php.exe' tests\error_unit.php
```

36件と25件を確認する。PHPの配置先が異なる場合はパスを合わせる。専用iniのextension_dirが相対extの場合は、PHPフォルダーを作業ディレクトリにして、スクリプト側を絶対パスで渡す。

## HTTPの108ケース

1. ソースの別コピーを使う。実用中のconfig.local.phpはコピーしない。
2. 空の `beta_security_test_run` を自分で作成し、ローカル保管のdatabase.sqlを読み込む。
3. tests/export_sql_fixtures.phpで生成したtest_data.sqlのUSE句をこの専用DB名へ合わせて読み込む。roles3件、system_locks1件、可変5テーブル各10件になる。
4. この専用DBだけで `UPDATE teachers SET must_change_password=0;` を実行する。テスト用アカウントはteacher1〜10@example.invalid、SqlTest123!。実用DBには使わない。
5. 接続先環境変数を検証用へ明示し、PHP開発サーバーを専用ルーターで起動する。すでに使用中のポートは使わない。

```powershell
$env:BETATEAM_DB_HOST = '127.0.0.1'
$env:BETATEAM_DB_PORT = '33318' # 自分が用意した専用DBのポートに合わせる
$env:BETATEAM_DB_NAME = 'beta_security_test_run'
$env:BETATEAM_DB_USER = 'root' # 専用試験環境のユーザー
$env:BETATEAM_SECURITY_TEST_MODE = '1'
& 'C:\xampp\php-8.2.35\php.exe' -S 127.0.0.1:33319 -t . tests\security_router.php
```

DBにパスワードがある場合はBETATEAM_DB_PASSWORDを安全に設定する。上のrootは隔離した試験DBの例であり、実用DBの接続は[専用ユーザー](DB接続権限.md)にする。検証用の別コピーにconfig.local.phpを作る場合も、この専用DBの設定だけにする。

別のPowerShellで、同じコピーの直下から実行する。

```powershell
$env:BETATEAM_SQL_TEST_HOST = '127.0.0.1'
$env:BETATEAM_SQL_TEST_PORT = '33318'
$env:BETATEAM_SQL_TEST_DATABASE = 'beta_security_test_run'
$env:BETATEAM_SQL_TEST_USER = 'root'
python tests\security_http.py --base-url http://127.0.0.1:33319/
```

SQL側のパスワードはBETATEAM_SQL_TEST_PASSWORD。未設定なら空文字。MySQL CLIが既定のC:/xampp/mysql/bin/mysql.exeと異なる場合はBETATEAM_MYSQL_CLIへ設定する。HTTP送信先と、ルーターが実際に読むDB設定のホスト・ポート・DB名の一致を最初のGETで検証する。不一致ならPOSTせず終了する。ルーター自体もCLI-server・試験モード・loopback接続・専用DB名を必須にし、Apacheからは利用できない。

試験は生徒・講師・担当・認証保留の前後比較を行い、終了時に架空データを復元する。認証によるrate_limitsの更新は残る。再実行時は、専用DBだけで `DELETE FROM rate_limits;` を行う。

この環境ではMySQL CLIが終了0でも出力を途中で欠落させる現象があったため、--unbufferedと終端マーカー・件数照合を使う。出力欠落を試験成功にしたり、再送で隠したりしない。

## 障害注入16ケース

```powershell
python tests\security_runtime.py --php 'C:\xampp\php-8.2.35\php.exe'
```

必要なら--iniで専用iniを指定する。OS一時領域にソースのコピーと検証サーバーを作り、設定不正、接続不能、模擬PDOエラー、セッション開始・保存・期限、ログ失敗、部分出力、致命的エラーを再現する。実DBは不要。OOMの試験を含むため、版確認で未修正PHPを拒否する。CVE修正版より古いPHPで強制実行しない。

## Apacheの66ケース

```powershell
python tests\apache_security.py --httpd 'C:\xampp\apache\bin\httpd.exe' --server-root 'C:\xampp\apache'
```

別ポート・一時Docroot・無害なファイルで現行.htaccessを試験する。既存Apache・設定・DBは変更しない。PHPをロードせず、通信量確認用のPython CGIだけを一時環境で使う。65,536バイトは許可、65,537バイトは413となることを確認する。

## 結果

output/security-http.json、security-runtime.json、apache-security.jsonに結果を保存する。失敗時の終了コードは1。失敗を削除・無視して完了扱いにしない。問い合わせID・安全なログ・内部情報非露出、HTTP状態、更新の有無も確認する。
