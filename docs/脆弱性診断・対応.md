# 脆弱性診断と対応

診断開始：2026年10月22日。PHP/XAMPPのβteam、同梱PHPMailer 7.1.1、JavaScriptとApache公開設定を対象とする。実DBへの攻撃、実データの改変、外部メールの送信は行わない。コードと専用環境での再現結果を根拠とし、診断済みであることを無欠陥の保証とはしない。

## 優先する検出事項

| ID | 重要度 | 診断時の根拠と影響 | 対応方針 |
|---|---|---|---|
| ENV-01 | 重大 | PHP 8.2.12を使用。公式が2026-10-21にCVE-2026-109618/109619を修正。アプリの実行前に到達しうるためコード修正では解消できない | 公式8.2.35を別フォルダーで検証。XAMPP切替は他プロジェクトにも影響するため範囲確認後に実施 |
| APP-01 | 中 | password_change.phpの現在パスワード照合に回数制限なし。認証済みセッションを悪用した反復試行が可能 | 講師単位で15分5回。429と待機時間 |
| APP-02 | 中 | auth.phpのend_loginが認証消去より先にDBへ接続。DB障害でログアウトが途中停止 | 認証消去を先に確定し、後始末だけを別に保護 |
| APP-03 | 中 | .gitignoreのbackup/archive除外と異なり、.htaccessはconfig.local.php.bak等を拒否しない。バックアップを置くと内容が配信されうる | バックアップ・アーカイブ・隠しファイルと内部用PHPの公開を拒否 |
| APP-04 | 中 | 設定読込とsession_startが共通例外処理より前。開始・保存の失敗を検出せず、偽の成功や診断不能につながる | 早期ハンドラ、出力バッファ、セッション開始/保存/ID更新の失敗検知 |
| APP-05 | 低 | 無操作期限のみで、継続利用中のセッションに絶対期限がない | ログインから8時間で再認証 |
| ERR-01 | 中 | 全例外を503にし、フォームの入力不正・競合・回数制限は200。監視と利用者の復旧判断が不正確 | 400/403/404/405/409/413/415/422/429/500/503を設計どおり分類 |
| ERR-02 | 低 | 不正UTF-8・NUL・DBで表現できない生年月日が保存処理へ届く | DB前に入力検証し422。容量・項目数超過は413 |
| ERR-03 | 低 | SMTP送信失敗の後始末でもDB例外が発生すると、元の案内が失われる | セッショントークン消去と後始末を分離し、安全な503と参照ID |

APP-03は危険なバックアップファイルが存在する場合の露出であり、現在の機密ファイルをダウンロードしたという意味ではない。ENV-01の実行コードを送る再現は行わず、実行バージョンと公式の影響範囲で判定する。

## 維持する防御

PDOのプレースホルダー、数値のページング、HTMLエスケープ、遷移先の許可リスト、サーバー側の権限判定、担当関係の再確認、編集version、管理ロック、CSRF、パスワードハッシュ、メールコードのハッシュ・期限・試行回数を確認する。JavaScriptはtextContentとDOM APIを使い、innerHTML・eval・秘密のブラウザ保存を使用していない。CSPを弱める修正は行わない。

## 依存関係・環境の根拠

- [PHP公式・2026-10-21の重大脆弱性告知](https://www.php.net/archive/2026.php#2026-10-21-5)：mod_phpも影響範囲。8.2系列の修正版は8.2.35。更新以外に完全な対策はない。
- [PHP公式Windows配布](https://www.php.net/downloads.php?os=windows&version=8.2)：XAMPPのApacheモジュール向けにはVS16 x64 Thread Safeを検証する。
- [PHPMailer公式アドバイザリー](https://github.com/PHPMailer/PHPMailer/security/advisories)：診断時点の公開情報と同梱版を照合する。過去の旧版向けCVEを現行版の欠陥と誤認しない。

HTTPS、DBユーザーの最小権限、バックアップ保管、PHP/Apache/MariaDBの継続更新は環境側でも必要。今回のコード変更だけでサーバー全体を保護したとは扱わない。
