# 脆弱性診断と対応

診断開始：2026年10月22日。PHP/XAMPPのβteam、同梱PHPMailer 7.1.1、JavaScriptとApache公開設定を対象とする。実DBへの攻撃、実データの改変、外部メールの送信は行わない。コードと専用環境での再現結果を根拠とし、診断済みであることを無欠陥の保証とはしない。

## 優先する検出事項

| ID | 重要度 | 診断時の根拠と影響 | 対応方針 |
|---|---|---|---|
| ENV-01 | 重大 | PHP 8.2.12を使用。公式が2026-10-21にCVE-2026-109618/109619を修正。アプリの実行前に到達しうるためコード修正では解消できない | 公式8.2.35を別フォルダーで検証し、更新手順を作成。利用者の指定により共有XAMPPの切替・Apache再起動は今回の対象外 |
| ENV-02 | 中 | 実設定がroot・空パスワードのDB接続であることを、値を出さない確認で検出 | チーム側で専用ユーザー・最小権限へ切り替える。手順とGRANT例を作成 |
| APP-01 | 中 | password_change.phpの現在パスワード照合に回数制限なし。認証済みセッションを悪用した反復試行が可能 | 講師単位で15分5回。429と待機時間 |
| APP-02 | 中 | auth.phpのend_loginが認証消去より先にDBへ接続。DB障害でログアウトが途中停止 | 認証消去を先に確定し、後始末だけを別に保護 |
| APP-03 | 中 | .gitignoreのbackup/archive除外と異なり、.htaccessはconfig.local.php.bak等を拒否しない。バックアップを置くと内容が配信されうる | バックアップ・アーカイブ・隠しファイルと内部用PHPの公開を拒否 |
| APP-04 | 中 | 設定読込とsession_startが共通例外処理より前。開始・保存の失敗を検出せず、偽の成功や診断不能につながる | 早期ハンドラ、出力バッファ、セッション開始/保存/ID更新の失敗検知 |
| APP-05 | 低 | 無操作期限のみで、継続利用中のセッションに絶対期限がない | ログインから8時間で再認証 |
| ERR-01 | 中 | 全例外を503にし、フォームの入力不正・競合・回数制限は200。監視と利用者の復旧判断が不正確 | 400/403/404/405/409/413/415/422/429/500/503を設計どおり分類 |
| ERR-02 | 低 | 不正UTF-8・NUL・DBで表現できない生年月日が保存処理へ届く | DB前に入力検証し422。容量・項目数超過は413 |
| ERR-03 | 低 | SMTP送信失敗の後始末でもDB例外が発生すると、元の案内が失われる | セッショントークン消去と後始末を分離し、安全な503と参照ID |

APP-03は危険なバックアップファイルが存在する場合の露出であり、現在の機密ファイルをダウンロードしたという意味ではない。ENV-01の実行コードを送る再現は行わず、実行バージョンと公式の影響範囲で判定する。

## 維持する防御

PDOのプレースホルダー、数値のページング、HTMLエスケープ、遷移先の許可リスト、サーバー側の権限判定、担当関係の再確認、編集version、管理ロック、CSRF、パスワードハッシュ、メールコードのハッシュ・期限・試行回数を確認する。JavaScriptはtextContentとDOM APIを使い、innerHTML・eval・秘密のブラウザ保存を使用していない。CSPを弱める修正は行わない。

## 実装と確認記録

設計は[エラーハンドリング設計](エラーハンドリング設計.md)。設計を先にGitへ保存した後、認証・共通エラー処理、Apacheの公開制限を別コミットで実装した。

| 対象 | 修正箇所 | 現在の状態 |
|---|---|---|
| APP-01 | password_change.php:12、functions.phpのconsume_limit | 講師ID単位で15分5回、新しいセッションの6回目も429。正しい照合でカウンター解除 |
| APP-02 | auth.php:61 | 認証消去・ID更新をDB後始末より先に実施。DB接続不能でもログアウト状態を維持 |
| APP-03 | .htaccess:2 | 隠しファイル、バックアップ、SQL、圧縮、内部PHPを拒否。64KiBの受信上限も設定 |
| APP-04 | errors.php:97、bootstrap.php | 設定前から捕捉。セッション開始・ID更新・終了時保存を確認し、失敗時は安全に停止 |
| APP-05 | auth.php:8 | 無操作30分とログインから8時間を別々に確認 |
| ERR-01 | errors.php、フォーム各処理 | 入力422、権限403、競合409、制限429、実装障害500、一時障害503等に分類 |
| ERR-02 | functions.php:58、services.php | UTF-8、制御文字、文字数、保存可能な日付、容量、項目数をDB前に検証 |
| ERR-03 | mailer.phpのdeliver_change | 送信失敗時にセッショントークンを先に除去、後始末失敗を分離して記録 |
| 追加不具合 | mailer.php:17 | PHPMailer本体の未定義Timelimitプロパティ指定を修正。SMTPインスタンスの正規プロパティへ設定 |

共通処理では、DB例外や設定内容を画面へ出さない。500/503の問い合わせIDをログと画面で一致させる。ログにはSQL、POST、パスワード、OTP、Cookie、メール、生の例外文を含めない。

フォームの入力値保持、エラー要約へのフォーカス、項目のaria-invalid、編集競合時の最新画面リンクもブラウザーで確認した。秘密の入力は再表示しない。JavaScriptにinnerHTMLやevalは導入していない。

## 検証結果

PHP 8.2.35、MariaDB 10.4.32の一時DB、外部へ配送しないSMTP、独立Apacheで実施。

| 確認 | 件数 | 結果 |
|---|---:|---|
| 既存単体 | 36 | 成功 |
| エラー分類・文字・復旧先の単体 | 25 | 成功 |
| HTTPセキュリティ回帰 | 108 | 全件成功、業務データの復元一致 |
| 障害注入 | 16ケース・169検証 | 全件成功。DBエラー分類の一部は模擬PDO例外、接続不能・セッション・設定・ログ・OOMは実際に注入 |
| 独立Apache | 66 | 全件成功、受信上限の前後とファイル取得拒否を確認 |
| 既存認証・生徒・講師・メール・再確認 | 17+24+22+27+6 | 全件成功。既存試験のHTTP期待値を新設計へ合わせた |
| 誤ったHTTP送信先の拒否 | 2条件 | 専用サーバーの一致を許可、異なる試験サーバーはPOST前に拒否 |
| 実Apacheの読み取り確認 | 13 | 全件成功。GETによる表示、内部ファイル拒否、メソッド拒否のみ |

MySQL CLIの出力が、終了0・stderrなしでも11,691から8,224バイトへ欠落する現象を400回中3回再現した。--unbuffered付き400回では欠落なし。試験プログラムに出力終端・各表の件数とJSON構造の検証を加え、欠落を成功扱いしないよう修正した。最終HTTP試験は108/108成功。失敗をskipした結果ではない。

実ApacheへのPOST確認は自動承認審査で実DBの試行回数更新の可能性を理由に拒否されたため、実環境の確認はGETだけへ変更した。送信処理は専用DBの試験で確認している。実DBの生成・変更、実パスワードの変更、外部SMTP送信は行っていない。

ソースと.htaccessは`C:\xampp\htdocs\βteam`へ反映済み。既存のSQL、各自の設定、READMEの移動は保持している。再実行方法は[セキュリティ検証手順](セキュリティ検証手順.md)。実行結果JSON・画面画像はローカルのoutputに保管する。

## 残件と診断の限界

- ENV-01：共有XAMPPはまだPHP 8.2.12。公式8.2.35のハッシュ照合と別環境での検証は完了。2026年10月22日の利用者指定により、今回はアプリ修正と[PHP更新手順](PHP更新手順.md)の作成までとし、共有PHPの切替・Apache再起動は実施しない。この重大リスクはアプリ修正だけでは解消していない。
- ENV-02：実DBのユーザー・権限は、チームが構築する方針に合わせて変更していない。[DB接続権限](DB接続権限.md)に専用ユーザーと必要な権限のSQLを記載した。
- 実際の外部SMTP・HTTPSの運用、MySQL 8.0本体、Apache共有モジュール切替後の他プロジェクトとの互換性は未確認。検証は上記の環境と経路に限る。
- サーバー全体の侵入試験、OS・Apache・MariaDBの全CVE照合は実施していない。これらの継続更新は別途必要。

差分を自己レビューし、再現した指摘は受け入れて修正した。検証したアプリ差分に未修正の必須指摘は残っていない。環境側の残件は上記のとおりで、診断結果を「脆弱性が一切ない」という保証にはしない。

## 依存関係・環境の根拠

- [PHP公式・2026-10-21の重大脆弱性告知](https://www.php.net/archive/2026.php#2026-10-21-5)：mod_phpも影響範囲。8.2系列の修正版は8.2.35。更新以外に完全な対策はない。
- [PHP公式Windows配布](https://www.php.net/downloads.php?os=windows&version=8.2)：XAMPPのApacheモジュール向けにはVS16 x64 Thread Safeを検証する。
- [PHPMailer公式アドバイザリー](https://github.com/PHPMailer/PHPMailer/security/advisories)：診断時点の公開情報と同梱版を照合する。過去の旧版向けCVEを現行版の欠陥と誤認しない。

HTTPS、DBユーザーの最小権限、バックアップ保管、PHP/Apache/MariaDBの継続更新は環境側でも必要。今回のコード変更だけでサーバー全体を保護したとは扱わない。
