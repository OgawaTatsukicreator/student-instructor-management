# 学習塾の生徒・講師管理

## 概要

学習塾の講師が、生徒情報と講師情報を管理するWebアプリケーションです。登録された講師がログインし、権限に応じて情報の閲覧・登録・編集・削除を行います。

XAMPP上のPHPで実装し、データベースにはMariaDB／MySQLを使用します。フレームワーク、Composer、画面のビルド作業は不要です。配置先は `C:\xampp\htdocs\βteam`、データベース名は `βteam` です。

| 管理する情報 | 項目 |
|---|---|
| 生徒 | 姓、名、担当講師、生年月日、特記事項 |
| 講師 | 姓、名、メールアドレス、権限、特記事項 |

生徒には担当講師を1名以上登録します。1人の生徒に複数の講師を割り当てられ、講師も複数の生徒を担当できます。どの権限の講師も担当者になれます。

### 権限

| 権限 | 生徒情報 | 講師情報 |
|---|---|---|
| `admin`（管理者） | 全生徒の閲覧・登録・編集・削除 | 全講師の閲覧・登録・編集・削除 |
| `operator`（運営担当） | 全生徒の閲覧・登録・編集・削除 | `operator`・`general`の閲覧 |
| `general`（一般講師） | 全生徒の閲覧、自分の担当生徒の特記事項のみ編集 | 利用不可 |

すべての講師が、自分のパスワード変更とログアウトを利用できます。

## ログイン方法

初めて設置する場合は、先に[初期セットアップ](#初期セットアップ)を行ってください。

1. XAMPPのApacheとデータベースが起動していることを確認します。
2. [ログイン画面](http://localhost:8080/%CE%B2team/login.php)を開きます。この環境のApacheは8080番です。別のPCでは実際のポートに合わせてください。
3. 登録済み講師のメールアドレスとパスワードを入力し、ログインを押します。
4. 初回ログインでは、初期パスワードを自分のパスワードへ変更します。
5. 変更が完了すると生徒一覧が開きます。

講師アカウントは管理者が登録します。初期パスワードは登録時に指定するため、管理者から受け取ってください。パスワードを忘れた場合も管理者へ連絡してください。アプリ内のパスワード再発行機能は未実装です。

### パスワードの条件

- 10文字以上50文字以内。
- 半角英大文字、半角英小文字、数字、記号のうち2種類以上を使用。
- 空白・全角文字は使用不可。記号はASCIIの印字可能文字を使用。
- 変更時は現在と異なるパスワードを指定。

ログイン状態は、無操作で30分、またはログインから8時間が経過すると終了します。試行回数の上限に達した場合は、画面の案内に従って時間をおいてから再試行してください。

## 使い方

左側のメニューから生徒情報・講師情報・パスワード変更へ移動します。メニューと操作ボタンは権限に応じて表示されます。スマートフォンでは右上のメニューボタンで開閉できます。

### 一覧の閲覧・検索

生徒一覧では氏名または担当講師名、講師一覧では氏名またはメールアドレスで検索します。検索語は100文字以内の部分一致です。閲覧できる全件を対象に検索し、ID順に20件ずつ表示します。ページを切り替えても検索語を保持します。解除を押すと全件表示に戻ります。

検索は両一覧を合わせてアカウントごとに1分間30回までです。上限に達した場合は、しばらく待ってから一覧を開き直してください。

氏名または詳細から詳しい情報を確認できます。生徒の特記事項は担当講師間の共有欄です。

### 登録・編集

1. 一覧の新規登録、または対象行の編集を選びます。
2. 必須項目を入力します。生徒の担当講師は複数選択できます。
3. 登録する、または保存するを押します。完了すると一覧へ戻り、メッセージを表示します。

講師登録では初期パスワードも設定し、本人へ伝えてください。一般講師は担当生徒の特記事項を編集から共有欄だけを更新できます。

入力エラーが出た場合は、表示された項目を修正します。パスワードは再入力してください。他の講師の更新と重なった場合は、最新の画面を開くから内容を確認して編集し直します。保存前に別の画面へ移動すると入力内容は失われます。

### 削除

対象の編集画面で削除を押し、確認画面で対象の氏名を確認して削除するを選びます。キャンセルで編集へ戻れます。削除した情報は元に戻せません。

担当生徒がいる講師は、先に担当を別の講師へ変更してください。自分自身の講師アカウントと最後の管理者は削除できません。自分の権限変更もできません。

### パスワード変更・ログアウト

パスワード変更で現在のパスワードと新しいパスワードを入力します。通常の変更後はログインしたまま元の画面へ戻り、完了メッセージを表示します。一覧の検索語とページ位置も保持します。他のログインセッションは次の操作時に再ログインが必要になります。

メール認証を有効にした環境では、続けて登録済みメールへ届く認証コードを入力します。設定方法は[メール認証](#メール認証)を参照してください。

利用を終えるときは、メニューのログアウトを押してください。

## 運用

### 初期セットアップ

アプリはPHP 8.2系で実装し、PHP 8.2.35とMariaDB 10.4.32の専用環境で動作確認しています。MySQL 8.0向けの設計も用意していますが、MySQL 8.0本体での確認は未実施です。必要なPHP拡張はPDO MySQLとmbstring、SMTPのTLS利用時にはOpenSSLです。運用前にPHPのセキュリティ更新を適用してください。共有XAMPPの更新計画は[PHP更新手順](docs/PHP更新手順.md)に記載しています。

1. プロジェクトを `C:\xampp\htdocs\βteam` へ配置し、Apacheとデータベースを起動します。
2. phpMyAdmin等で、文字コードutf8mb4の空のデータベース `βteam` を作成します。DB本体の作成はチームで行います。
3. `βteam` を選択し、チーム内で受け取った `database.sql` を読み込みます。SQLはGit管理外なので、新しくcloneしたPCでは別途受け取ってください。既存DBへ重ねて実行せず、必要なデータをバックアップしてから空のDBを用意してください。
4. `config.example.php` を `config.local.php` にコピーし、DBのホスト・ポート・ユーザー・パスワードを設定します。この環境のDBポートは3307番です。接続にはアプリ専用のユーザーを使ってください。必要な権限は[DB接続権限](docs/DB接続権限.md)を参照してください。
5. Apacheの`mod_rewrite`と`AllowOverride`を有効にし、同梱の`.htaccess`が適用されることを確認します。資料、設定、SQL、ログなどの直接取得を拒否する設定です。
6. プロジェクト直下でPowerShellを開き、次のコマンドを実行します。姓・名・メールアドレス・初期パスワードを入力してください。

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\setup_admin.ps1
   ```

7. ログイン画面を開き、作成した管理者でログインします。

初期管理者の作成は、講師が1件も登録されていない場合だけ実行できます。既に講師がいる場合は、ログインした管理者が画面から追加してください。PowerShellを使わない場合は、`C:\xampp\php\php.exe setup_admin.php`の標準入力へ`last_name`・`first_name`・`email`・`password`を持つJSONを渡せます。パスワードをコマンド引数や履歴へ残さないでください。

### メール認証

初期状態ではメール認証は無効です。利用する場合はSMTPを用意し、`config.local.php`で次を設定します。

- `mail_verification`を`true`にする。
- `app_key`に32文字以上のランダムな秘密鍵を設定する。
- `smtp`にホスト、ポート、送信元、必要な認証情報を設定する。`security`はSTARTTLSなら`tls`、暗黙TLSなら`ssl`を指定する。

秘密鍵は次のコマンドで生成できます。出力した値を設定ファイルに保存し、Gitへ含めないでください。

```powershell
C:\xampp\php\php.exe -r "echo bin2hex(random_bytes(32));"
```

認証コードは6桁、有効期限は10分、誤入力は5回までです。再送間隔は60秒以上、送信試行は失敗分を含めて1時間に5回までです。再送すると前のコードは無効になります。送信失敗時はパスワードを変更しません。証明書検証を有効にし、暗号化なしの`none`はローカル試験用SMTPだけに使用してください。

### 日常の管理・バックアップ

実運用の通信にはHTTPSを使い、PHP・Apache・データベースを継続して更新してください。アプリの改修と共有PHPの更新・Apache再起動は別の作業です。

データベースは定期的にエクスポートし、復元できることを確認します。SQL、バックアップ、`config.local.php`、SMTP認証情報、生徒の個人情報、`runtime/`と`output/`の記録をGitへ含めないでください。バックアップはWeb公開ディレクトリの外へ保管します。

期限切れの制限・メール認証レコードは、管理者が`maintenance.php`で対象件数を確認し、`maintenance.php --prune`で各1000行まで削除できます。通常は1日1回を目安に確認します。接続先を確認してから実行してください。手順と未実施の基盤更新は[サーバー運用強化手順](docs/サーバー運用強化手順.md)に記載しています。アプリ単独で回線へのDDoSを防ぐことはできないため、公開時は前段の接続数・通信量制限も必要です。

提出時は完成したDBをエクスポートしたSQLと必要なソースを同じディレクトリに格納し、ZIPにします。`database.sql`は初期定義です。提出用の最終エクスポートを別途作成し、接続設定の秘密情報や不要な実行記録が混入していないことを確認してください。

### エラーが出た場合

| 表示・状態 | 対応 |
|---|---|
| 操作の有効期限切れ | 画面を開き直して操作し直す。ログイン画面に戻った場合は再ログインする |
| 入力エラー・他の利用者との編集競合 | 案内された項目を修正するか、最新の画面を開いて保存内容を確認する |
| 試行回数の上限 | 時間をおいてから再試行する |
| 処理中の問題・一時的な障害 | 連打せず処理結果を確認し、表示された問い合わせIDを管理者へ伝える |

管理者は`runtime/application.log`を確認します。診断とエラーの設計は[脆弱性診断・対応](docs/脆弱性診断・対応.md)と[エラーハンドリング設計](docs/エラーハンドリング設計.md)を参照してください。
